## 2. 浏览器检查：只留一个HTML并断网

```bash
node tools/check_offline_docs_browser.cjs
```

此项需要预先安装Playwright及其Chromium；只阅读HTML不需要这些依赖。若使用已有Chromium，可设置环境变量 `NCCL_DOCS_CHROMIUM` 指向可执行文件。可选的第一个命令行参数是截图证据输出目录。

脚本将每份HTML单独复制到临时空目录，通过file://打开并关闭网络。本轮实际通过：

- 图解新旧两个名称：各15个集合通信画面、7种原语；所有图片解码成功。
- 函数搜索新旧两个名称：搜索、零结果、显示更多、F编号hash跳转、步骤及内嵌完整函数体展开。
- 1280像素与390像素宽度的布局检查。
- 共四个独立页面；30次逐轮画面、14次原语切换；HTTP请求0次、页面异常0次。
- 查看截图确认中文、图形和正文可读。Linux测试环境需有中文字体；页面不下载远程字体，Windows可使用系统微软雅黑。

## 3. HTML怎样从文档重建

```bash
python3 tools/build_offline_docs.py
```

生成器仅用Python标准库。源码对照页先运行 `python3 tools/build_source_diagram_reader.py`，再运行 `python3 tools/build_offline_docs.py`。它读取01图解、09修正记录、visuals及function-logic数据，输出用途明确的两份HTML，并刷新旧HTML兼容入口。函数体来自logic目录相应F编号章节；没有找到函数体会报错，避免生成不完整的“离线搜索”。

图解图片与交互均内嵌，不加载CDN、脚本、SVG侧文件或在线字体。源码及其他Markdown章节的在线参考链接仍需要网络；完整源码ZIP可用本地编辑器离线阅读这些文件。新增源码注释后应更新相应符号行号和注释文件哈希；原始Git blob字段不可改成注释后内容以掩盖执行代码变化。

## 4. 分发检查

完整ZIP采用明确的中文用途名称，只包含源码、文档及工具，不包含git元数据、Python缓存或临时分析文件。独立解压后逐文件比较字节，并在解压目录重跑上述三项标准库检查。HTML额外以“只下载单个文件”的方式执行浏览器回归，避免仅在完整工作目录里通过。

## 5. 尚未验证的内容

当前环境无nvcc/CUDA GPU，未执行CUDA编译、GPU正确性或多机性能测试。内部步骤是静态语句结构展开，带有关键路径人工解释；它不是完整编译器CFG、宏展开、C++重载解析或并发协议证明。覆盖清单包含附带NVTX/ABI代码，不代表这些代码负责通信或已逐函数人工验证。
