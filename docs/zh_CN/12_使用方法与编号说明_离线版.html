2. 最容易上手的阅读方法

  1. 打开11对照页，点击顶部 “Simple genericOp”。不用输入编号。
  2. 在右侧“选择本文件的代码主题”中，选择 “先等连接并建立共享指针”。左侧会定位到对应代码，右侧解释waitPeer与等待条件。
  3. 再选 “普通多源多目标融合归约”，看它怎样组织输入、输出并调用ReduceOrCopyMulti。
  4. 最后选 “空slice和非worker仍需参与”，结合源码看为什么没有有效数据时仍需同步和推进。
  5. 看不清图中文字时点 “放大图示”，按Esc关闭。随时点 “使用方法” 或 “编号说明” 查阅帮助。

理解原语后，再点顶部“Ring AllReduce”，按“首发本地块 → 中间部分和归约转发 → 完成本块归约并开始结果传播 → 只复制已完整结果 → 最后接收”阅读。你可以按中文主题选位置，不必背函数编号。

3. 注释里的编号是什么意思

下面这些是我给中文讲解增加的“定位号”，不是NCCL的GPU编号、rank编号或硬件资源编号。 后面的数字只用来区分条目，不代表源码行号、执行顺序、运行次数或资源数量。

写法含义你怎么用
F0232函数定位号；本版对应Simple的genericOp在11对照页或05函数搜索页输入完整编号，能找到这个具体函数
T0181类型定位号；本版对应ncclConnInfo在11对照页查结构体/类/联合体/枚举；这里T表示类型条目
V开头的编号某处变量或结构体字段的定位号在11对照页定位具体声明，方便区分不同函数中的同名变量
B0007源码与图示的对应位置；本版是AR完成本块归约并开始传播在11对照页搜索，或点击左侧源码注释中的这个编号，直接看对应代码和图
M开头的编号宏的定位号在源码或11对照页查对应宏定义
P开头的编号参数读取函数生成项，例如NCCL_PARAM生成的getter用来查环境参数的读取与默认值；它不是图中表示rank总数的P
X开头的四位编号常量、枚举项或接口声明等条目的定位号结合紧邻的“中文逐项-常量/枚举项/接口”标题识别；它不是归约图里的X0输入贡献

例如 F0058 定位到AllReduce的runRing，B0007 定位到该函数中“完成本块归约并开始结果传播”的具体代码段。一个函数可以有多处看图位置，同一张图也可以关联多个函数。

可以直接按函数名和中文主题使用页面，不需要记F/T/V/B。 编号主要用于精确查找、区分同名条目和互相交流位置。原有编号和跳转链接继续有效。

4. 图中的C0、X0等记号又是什么意思

图中记号含义容易混淆的地方
rank 0、rank 1本次communicator中参与者的编号不一定等于本机CUDA设备序号；同一GPU在不同communicator中也可能有不同rank
C0、C1、C2示例中的第0、1、2个数据块或逻辑段C0不是channel 0；AR与AG/RS的分块归属须看对应图的说明
X0(C2)rank 0输入中的第2块前一个数字说明“谁贡献的”，括号里的数字说明“哪一块”
图里简写的X0、X1当前所画数据块来自rank 0、rank 1的贡献和源码注释定位号X0221是两套记号，按上下文区分
P、C本文分片公式中，P通常表示rank总数，C表示本次使用的channel数以公式所在段落的定义为准，不是注释编号
模板里的TC++模板的数据元素类型，例如float它和注释定位号T0181不同
tid当前线程组中的线程编号不是GPU rank；线程组拆分时需看该处的赋值
step连接循环缓冲的协议进度不是WQE数量、网络包数量或源码的步骤编号
slice、chunk原语片段、算法分块一个chunk可以继续分成slice；有效长度和协议进度跨度也不同

以4个rank对同一块C2做Sum为例，最终内容是 X0(C2)+X1(C2)+X2(C2)+X3(C2)。这里“四份贡献”和“第2块”是不同维度。AllGather只拼接各rank的段，不执行这个求和；不能把几段并排显示误读成归约。

5. 在普通编辑器中怎么查图

普通.cc/.h文本注释不能直接显示SVG。源码中增加了“中文精读：图示绑定”说明，列出中文主题、B定位号和图名。

读到想看图的地方，可以打开11对照页，搜索对应函数名或B编号。要源码和图并排阅读，直接使用11对照页最方便。IDE适合继续修改、调试或编译真实源码。

6. 遇到这些情况怎么处理

现象处理方法

右侧显示“暂无专属图示”当前辅助函数或代码行尚无人工绑定；可选本文件的其他主题。未绑定不表示源码没有作用
