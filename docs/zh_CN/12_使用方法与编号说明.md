# NCCL源码图解：使用方法与编号速查

**先记住一个入口：打开 `11_源码注释与图示对照_离线版.html`。** 左边是源码和中文注释，右边是当前代码对应的图与分析。开始阅读不需要记任何编号，也不用安装Python、Node或编辑器插件。

## 1. 第一次怎么打开

1. 只下载“源码注释与图示对照”HTML：用Edge或Chrome打开这个文件，即可离线看源码、注释和图。
2. 下载完整ZIP：先右键“全部解压”，再进入 `docs/zh_CN/`，打开 `11_源码注释与图示对照_离线版.html`。
3. GitHub网页只显示HTML代码时，先点“Download raw file”下载，再用浏览器打开。不要在文本编辑器里把HTML当普通源码阅读。

单独下载11对照页，内部的源码搜索、代码定位、图示反查都能用。要在11、01、05等不同HTML之间来回跳转，请完整解压ZIP并保留原目录。

| 文件 | 什么时候打开 |
| --- | --- |
| `11_源码注释与图示对照_离线版.html` | 日常主入口：边读源码和注释，边看对应图 |
| `12_使用方法与编号说明_离线版.html` | 忘了怎么操作、看不懂编号时查阅；11页面内也有“使用方法”和“编号说明”按钮 |
| `01_通信原语与算法图解_离线版.html` | 想先看总体原理、切换通信轮次与原语图 |
| `05_全部函数内部步骤_离线搜索.html` | 按函数名搜索并展开内部步骤、完整函数体；此页主要检索函数 |
| `src/`中的`.cc/.h/.cu`文件 | 想在IDE或文本编辑器里读、修改、编译真正的源码 |

## 2. 最容易上手的阅读方法

1. 打开11对照页，点击顶部 **“Simple genericOp”**。不用输入编号。
2. 在右侧“选择本文件的代码主题”中，选择 **“先等连接并建立共享指针”**。左侧会定位到对应代码，右侧解释waitPeer与等待条件。
3. 再选 **“普通多源多目标融合归约”**，看它怎样组织输入、输出并调用ReduceOrCopyMulti。
4. 最后选 **“空slice和非worker仍需参与”**，结合源码看为什么没有有效数据时仍需同步和推进。
5. 看不清图中文字时点 **“放大图示”**，按Esc关闭。随时点 **“使用方法”** 或 **“编号说明”** 查阅帮助。

理解原语后，再点顶部“Ring AllReduce”，按“首发本地块 → 中间部分和归约转发 → 完成本块归约并开始结果传播 → 只复制已完整结果 → 最后接收”阅读。你可以按中文主题选位置，不必背函数编号。

| 页面操作 | 作用 |
| --- | --- |
| 搜索`genericOp`、`waitPeer`等函数名 | 找函数；同名函数可根据文件路径区分 |
| 搜索`ncclConnInfo`等结构体名 | 找类型与字段 |
| 搜索`sliceSize`等变量名 | 找对应变量或字段；同名变量需要结合文件、所在函数区分 |
| 点击左侧行号 | 黄色标出当前行，右侧显示已有的对应图示 |
| 勾选“滚动源码时跟随图示” | 滚动源码时按所在代码段切换图与分析 |
| 取消“滚动源码时跟随图示” | 看图时保持当前位置，避免滚动源码使图切走 |
| 上一处 / 下一处 | 按本文件的代码主题继续阅读 |
| 按图示反查源码 | 先挑一张图，再点击关联函数或代码主题返回源码 |
| 当前定位链接 | 记录当前阅读位置；编号由页面自动生成，不用手写 |

黄色表示当前行，浅蓝色表示这一张图对应的代码范围。图说明的是逻辑关系，不能把图中的每个箭头直接当成一次kernel、一个QP或一条WQE。

## 3. 注释里的编号是什么意思

**下面这些是我给中文讲解增加的“定位号”，不是NCCL的GPU编号、rank编号或硬件资源编号。** 后面的数字只用来区分条目，不代表源码行号、执行顺序、运行次数或资源数量。

| 写法 | 含义 | 你怎么用 |
| --- | --- | --- |
| `F0232` | 函数定位号；本版对应Simple的`genericOp` | 在11对照页或05函数搜索页输入完整编号，能找到这个具体函数 |
| `T0181` | 类型定位号；本版对应`ncclConnInfo` | 在11对照页查结构体/类/联合体/枚举；这里T表示类型条目 |
| `V`开头的编号 | 某处变量或结构体字段的定位号 | 在11对照页定位具体声明，方便区分不同函数中的同名变量 |
| `B0007` | 源码与图示的对应位置；本版是AR完成本块归约并开始传播 | 在11对照页搜索，或点击左侧源码注释中的这个编号，直接看对应代码和图 |
| `M`开头的编号 | 宏的定位号 | 在源码或11对照页查对应宏定义 |
| `P`开头的编号 | 参数读取函数生成项，例如`NCCL_PARAM`生成的getter | 用来查环境参数的读取与默认值；它不是图中表示rank总数的P |
| `X`开头的四位编号 | 常量、枚举项或接口声明等条目的定位号 | 结合紧邻的“中文逐项-常量/枚举项/接口”标题识别；它不是归约图里的X0输入贡献 |

例如 `F0058` 定位到AllReduce的`runRing`，`B0007` 定位到该函数中“完成本块归约并开始结果传播”的具体代码段。一个函数可以有多处看图位置，同一张图也可以关联多个函数。

**可以直接按函数名和中文主题使用页面，不需要记F/T/V/B。** 编号主要用于精确查找、区分同名条目和互相交流位置。原有编号和跳转链接继续有效。

## 4. 图中的C0、X0等记号又是什么意思

| 图中记号 | 含义 | 容易混淆的地方 |
| --- | --- | --- |
| `rank 0`、`rank 1` | 本次communicator中参与者的编号 | 不一定等于本机CUDA设备序号；同一GPU在不同communicator中也可能有不同rank |
| `C0`、`C1`、`C2` | 示例中的第0、1、2个数据块或逻辑段 | C0不是channel 0；AR与AG/RS的分块归属须看对应图的说明 |
| `X0(C2)` | rank 0输入中的第2块 | 前一个数字说明“谁贡献的”，括号里的数字说明“哪一块” |
| 图里简写的`X0`、`X1` | 当前所画数据块来自rank 0、rank 1的贡献 | 和源码注释定位号X0221是两套记号，按上下文区分 |
| `P`、`C` | 本文分片公式中，P通常表示rank总数，C表示本次使用的channel数 | 以公式所在段落的定义为准，不是注释编号 |
| 模板里的`T` | C++模板的数据元素类型，例如float | 它和注释定位号T0181不同 |
| `tid` | 当前线程组中的线程编号 | 不是GPU rank；线程组拆分时需看该处的赋值 |
| `step` | 连接循环缓冲的协议进度 | 不是WQE数量、网络包数量或源码的步骤编号 |
| `slice`、`chunk` | 原语片段、算法分块 | 一个chunk可以继续分成slice；有效长度和协议进度跨度也不同 |

以4个rank对同一块C2做Sum为例，最终内容是 `X0(C2)+X1(C2)+X2(C2)+X3(C2)`。这里“四份贡献”和“第2块”是不同维度。AllGather只拼接各rank的段，不执行这个求和；不能把几段并排显示误读成归约。

## 5. 在普通编辑器中怎么查图

普通`.cc/.h`文本注释不能直接显示SVG。源码中增加了“中文精读：图示绑定”说明，列出中文主题、B定位号和图名。

读到想看图的地方，可以打开11对照页，搜索对应函数名或B编号。要源码和图并排阅读，直接使用11对照页最方便。IDE适合继续修改、调试或编译真实源码。

## 6. 遇到这些情况怎么处理

| 现象 | 处理方法 |
| --- | --- |
| 打开后满屏HTML标签 | 用浏览器打开`.html`，不要用记事本；确认文件没有被保存成`.html.txt` |
| 点击“在图解页打开”找不到文件 | 完整解压ZIP，保留`docs/zh_CN`下各HTML的相对位置；单独下载11页时用其内部图示即可 |
| 编号搜不到 | 输入完整编号并保留前导0；或者直接搜函数名。T/V/B/M/P/X请在11对照页查，05页主要搜索F函数 |
| 变量名出现很多结果 | 看文件路径和行号，再结合所在函数/结构体选择具体声明 |
| 右侧显示“暂无专属图示” | 当前辅助函数或代码行尚无人工绑定；可选本文件的其他主题。未绑定不表示源码没有作用 |
| 滚动后图自动切换了 | 取消“滚动源码时跟随图示”，需要时再勾选 |
| 图里文字太小 | 点击“放大图示”，或用浏览器缩放 |
| 从GitHub下载后没有中文注释 | 选择`codex/nccl-2.12.12-full-source-walkthrough`分析分支或使用本次完整ZIP；原始master保留原版代码 |
